popular_books = """
SELECT B.book_id, B.title, COUNT(c.checkout_id) AS COUNT
FROM BOOKS B
JOIN CHECKOUTS C
ON B.book_id = C.book_id
GROUP BY B.book_id

Fifth Question:
What does a neighborhood'activity look like further back in time?
I chose Maadi, I make join between members table and checkouts table by member id
I filter by using where to show only what in Maadi, then order by checkout date to show from newest to oldest
And looking past the ten most recent by using limit and offset
And select member id, first name, neighborhood, checkout date
SQL QUERY:
maadi = """
SELECT all columns
FROM MEMBERS M
JOIN CHECKOUTS C
ON M.member_id = C.member_id
WHERE M.neighborhood = "Maadi"
ORDER BY C.checkout_date DESC
LIMIT 10 OFFSET 10
"""
print("Neighborhood is Maadi")
sql_query(maadi)

(B)Difference between gathering data from web page and API:
 1-Web page:
 It is built for humans to view on a browser
 It returns the whole page as HTML that we must clean to pull out what we need
 The page's layout can change at any time, so the code we wrote can suddenly stop working
 It needs more work that we must search through the page tags
 If the website doesn't have an API, so we scrape the data from web page
 2-API:
 It is built for programs to read directly
 It returns organized, tidy, ready to use data usually as JSON
 The data structure rarely changes
 It is much easier than getting data from a web page
 If the website has an API, we use it as it is an official door the website opens for us
Why it matters in this project?
 Because library data as checkouts changes all the time
 API gives us a reliable way to get live updates
 Web page is risky because if the website updates its design, our code stops working
Result from my work:
 API(as json file): when it is read, it changes directly into a dataframe ready for merging
 Web page(as html file): when it is read, it returns a list containing the table,
  so I have to extract the first table(html[0]) as a dataframe to be able to merge it
